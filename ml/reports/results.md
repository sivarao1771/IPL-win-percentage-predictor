# IPL chase win probability: results

**Summary.** On the test seasons (2025-2026, 138 matches), the final model (gradient-boosted trees) did not beat the logistic-regression baseline B1 on log loss, the selection metric: final vs B1 accuracy 77.46% vs 78.35%, log loss 0.4846 vs 0.4695, Brier 0.1561 vs 0.1515. The paired 95% interval for the log-loss difference (final - B1, resampling whole test matches) is -0.0389 to +0.0743, which includes 0, so the difference is within the noise.

By phase, log loss final vs B1: overs 1-6: 0.6349 vs 0.6478; overs 7-15: 0.4714 vs 0.3989; overs 16-20: 0.2487 vs 0.3296. Both models are far better than always predicting the base rate (log loss 0.6891).

Generated by `ml/evaluate.py`. Every number below is copied from `metrics.json`, which keeps full precision; tables show 4 decimal places (accuracy as a percentage with 2).

**Metrics.** Accuracy: share of rows where the side of 50% matched the result. Log loss: penalty for the probability given to what actually happened; lower is better, a constant 50% guess scores 0.6931. Brier score: mean squared gap between probability and result; lower is better, a constant 50% guess scores 0.25.

**How the main model was picked.** Keep grid settings whose validation log loss is within 1% of the lowest. Among those, prefer monotonic, then the simplest by trees x leaves, then the higher learning rate.

The lowest validation log loss was 0.3803 (`{'learning_rate': 0.1, 'max_iter': 50, 'max_leaf_nodes': 31, 'min_samples_leaf': 100, 'monotonic': True}`), at the edge of the grid for learning_rate, max_leaf_nodes. One season of 70 matches cannot separate most settings: for 63 of 72 the paired 95% interval of the difference from the lowest includes 0. So the edge carries little information, and the rule picks among the 8 settings within the margin instead of trusting the single lowest. The paired intervals are shown for information; they are not used to select, because with this little data they also fail to rule out clearly weaker models.

## 4. Leakage demonstration

**Not a result of this project.** It shows how the old notebook's evaluation inflated scores. All rows except the last use all seasons' data (2008-2026) with an 80/20 split. With a random row split, every test match also has rows in training, so a model can recognise the match instead of predicting it. How much it gains depends on whether the model can memorise: the final model's settings (small trees, at least 100 rows per leaf) can do so far less than the old notebook's Random Forest (150 trees, depth 20, at least 5 rows per leaf).

| Test rows picked by | Model | Features | Test matches also in training | Accuracy | Log loss | Brier |
|---|---|---|---|---|---|---|
| Random rows (old notebook method) | Final model settings | match state | 1185 of 1185 | 79.48% | 0.4124 | 0.1359 |
| Random rows (old notebook method) | Final model settings | match state + team/city | 1185 of 1185 | 82.35% | 0.3753 | 0.1199 |
| Random matches | Final model settings | match state | 0 of 237 | 77.57% | 0.4422 | 0.1476 |
| Random matches | Final model settings | match state + team/city | 0 of 237 | 77.55% | 0.4424 | 0.1466 |

## 5. Future work

The test seasons 2025-2026 have now been used. Any change below must be judged on a new, untouched test season (2027 or later), not on 2025-2026 again.

- **Recency weighting:** give recent seasons more weight in training, to test whether the calibration gap in sections 2-3 comes from the game changing over time (for example the Impact Player rule).
- **Multi-season (rolling) validation:** choose settings by training on all seasons before each of several recent seasons and scoring on that season, instead of on 2024 alone. About 400 validation matches instead of 70 would make differences between settings measurable.
